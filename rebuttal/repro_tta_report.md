# Воспроизведение TGPO/SAGE MATH-500 из bliskavets/TTA (exp_10)

Дата: 2026-07-17. Машина: 1x H200 (общая с кампанией B3), vLLM 0.11.0, Qwen/Qwen3-8B-FP8,
localhost:9090 (живой сервер кампании, дефолты скриптов TTA совпали).

## Что запускалось

Оригинальный код без изменений логики: `exp_10/math500/test_new_method.py`
+ `exp_10/configs/math500.txt` (judge-промпт, порог 75%) + `math500_config.jsons`.
Конфиг основных результатов статьи: 2 optimization-эпохи x 7 генераций, seed 7,
подмножество 50 задач (детерминированная перетасовка из eval_module/math500eval.py —
никакого фильтра по сложности в коде НЕТ; "subset" в статье = random-50 seed 7).

Локальные правки только инфраструктурные: (1) стаб langfuse.observe; (2) убран
захардкоженный OpenAI-ключ; (3) грейдинг MATH_EXACT_MATCH=1 (сравнение \boxed{} с
эталоном) вместо недоступного o3-судьи — нижняя оценка точности.

## Результат

| Метрика | Значение |
|---|---|
| Точность (as-is, exact match) | 36/50 = 72.0% |
| Точность с o3-судьёй (openai/o3 через OpenRouter, тот же critic-промпт из helpers.py) | 37/50 = 74.0% |
| Расхождения o3 vs exact match | 1 задача (idx 318, \dfrac vs \frac) |
| Ответов вообще без \boxed{} | 11/50 = 22% |
| Точность среди завершённых (boxed) ответов | 36/39 = 92.3% |

Для сравнения: статья заявляет 92.0 (full 500); кампания на исправленном харнессе
(chat template, enable_thinking=false) — 88.3+/-0.6 (full 500, 3 сида).

## Разбор 11 ответов без \boxed{}

- 3 шт. длиной 11.8-13.6k символов: runaway CoT, обрезанный на max_tokens=4096 —
  прямое следствие бага ` /nothink` в AugEngine (raw /v1/completions без chat template
  не выключает thinking у Qwen3).
- 8 шт. коротких (0.4-1.4k): судья выбрал лучшим кандидата без финального ответа —
  в math-конфиге единственный аспект verification, нет проверки полноты
  (в отличие от AlpacaEval-конфига с is_incomplete).

## Вывод

Код запускается и механически воспроизводим end-to-end, но число 92.0 НЕ
воспроизводится: честные 72-74% на seed-7 подмножестве (bootstrap 95% CI примерно
[62, 86]). Разрыв почти целиком объясняется 22% незавершённых ответов. Точность
среди завершённых (92.3%) совпадает с заявленными 92.0 — вероятно, исходное число
получено в прогонах, где обрезки были реже или обрабатывались (другой max_tokens /
конфиг сервера / повторные запуски). Это независимо подтверждает решение кампании:
в AAAI-версии репортить 88.3+/-0.6 на исправленном харнессе.

Файлы: full50/math500_eval_20260717_160604.jsonl (по-задачные записи), full50.log.

## Починка поведения (2026-07-17, вечер)

Диагноз: промпт и параметры генерации в порядке (суффикс "Return the final answer
within \boxed{...}", max_tokens 4096, temp 0.7/0.8/0.9, top_p 0.95). Сломан транспорт:
AugEngine шлёт raw /v1/completions с суффиксом ' /nothink' без chat template — soft-switch
Qwen3 так не работает. Фикс (перенесён из rebuttal/core/vllm_client.py кампании): промпт
оборачивается в Qwen3 chat template с префиллом пустого <think></think> в assistant-ходе
+ stop-токен <|im_end|>; /v1/completions сохранён ради logprobs для margin. Метод SAGE
не менялся. Файл: eval_module/utils/vllm_client.py (_prepare_nonthink).

Результаты на том же подмножестве (50 задач, seed 7, o3-судья):

| Вариант | Точность | Без \boxed{} | Время |
|---|---|---|---|
| Baseline greedy (fixed engine) | 34/50 = 68.0% | 0 | ~2 мин |
| SAGE, оригинальный код (/nothink-баг) | 37/50 = 74.0% | 11/50 | ~120 мин |
| SAGE, починенный движок | 39/50 = 78.0% | 0 | ~20 мин |

- Обрезки устранены полностью (0/50), время SAGE-рана упало в ~6 раз.
- SAGE над baseline: +10 пт, discordant 5-0 в пользу SAGE (ни одной задачи, где SAGE
  хуже baseline), McNemar exact p=0.062 (N=50 мало для значимости).
- Подмножество seed 7 заметно СЛОЖНЕЕ среднего MATH-500: baseline 68% против 83.8%
  на полных 500. Вероятно, это и есть то "сложное подмножество" из старых экспериментов.
- Прирост +10 пт на сложном сабсете согласуется с кампанией (+4.5 на полных 500).
